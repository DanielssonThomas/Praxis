# Hermes integration feasibility

This review inspected upstream Hermes Agent v0.23.3 documentation at commit `caafe5389ae585ef77387a962aee05b1bcf17029`. The foundation environment had no Hermes executable on its PATH. The documented surfaces below are candidates for Praxis integration. A real fixture and observed version, operating system and surface are required before claiming compatibility.

| Area | Documented surface | Verification still needed |
| --- | --- | --- |
| Assignment create and inspect | Native Kanban provides machine-readable create, show and run history commands. Its gateway owns dispatch, and the dashboard plugin documents a task event stream. [Kanban reference](https://github.com/NousResearch/hermes-agent/blob/caafe5389ae585ef77387a962aee05b1bcf17029/website/docs/user-guide/features/kanban.md#cli-command-reference) | [#5](https://github.com/DanielssonThomas/Praxis/issues/5) must exercise a real assignment, map native IDs and states, and verify the available output, event ordering and fixture credentials. |
| Stop and reconnect | The Kanban dashboard plugin documents a terminate verb for reclaimable runs, with possible re-dispatch. The Runs API documents stop for a gateway agent turn and separate persisted session history. [Kanban worker visibility](https://github.com/NousResearch/hermes-agent/blob/caafe5389ae585ef77387a962aee05b1bcf17029/website/docs/user-guide/features/kanban.md#worker-visibility-endpoints) · [Runs API](https://github.com/NousResearch/hermes-agent/blob/caafe5389ae585ef77387a962aee05b1bcf17029/website/docs/user-guide/features/api-server.md#runs-api-streaming-friendly-alternative) · [Sessions](https://github.com/NousResearch/hermes-agent/blob/caafe5389ae585ef77387a962aee05b1bcf17029/website/docs/user-guide/sessions.md#authenticated-gateway-session-access-and-attribution) | [#5](https://github.com/DanielssonThomas/Praxis/issues/5) must identify authorized stop behavior for the selected assignment surface, including whether the assignment is requeued, and verify that UI exit and reconnect preserve runtime work. |
| Foreground and background manager | Hermes documents separate profile homes and gateways. Its Runs API offers polling, streaming and session history with surface-specific ownership and continuation rules. [Profiles](https://github.com/NousResearch/hermes-agent/blob/caafe5389ae585ef77387a962aee05b1bcf17029/website/docs/user-guide/profiles.md) · [Runs API](https://github.com/NousResearch/hermes-agent/blob/caafe5389ae585ef77387a962aee05b1bcf17029/website/docs/user-guide/features/api-server.md#runs-api-streaming-friendly-alternative) | [#16](https://github.com/DanielssonThomas/Praxis/issues/16), [#17](https://github.com/DanielssonThomas/Praxis/issues/17) and [#18](https://github.com/DanielssonThomas/Praxis/issues/18) must establish installation, independent foreground/background contexts, session controls, observed context usage and compaction data. |
| MCP and approvals | Hermes documents stdio and HTTP MCP clients, tool filtering and feature detection for run approvals. [MCP reference](https://github.com/NousResearch/hermes-agent/blob/caafe5389ae585ef77387a962aee05b1bcf17029/website/docs/user-guide/features/mcp.md#two-kinds-of-mcp-servers) · [API Server](https://github.com/NousResearch/hermes-agent/blob/caafe5389ae585ef77387a962aee05b1bcf17029/website/docs/user-guide/features/api-server.md#get-v1capabilities) | [#7](https://github.com/DanielssonThomas/Praxis/issues/7) must run a real MCP call, and [#11](https://github.com/DanielssonThomas/Praxis/issues/11) must demonstrate caller identity and effective scoped approval at execution. |
| Axiom qualification | Axiom's Hermes adapter issue records a native Linux CLI fixture. Installed bundle qualification and release validation are tracked separately. [Adapter evidence](https://github.com/DanielssonThomas/Axiom/issues/15) · [Installed-host matrix](https://github.com/DanielssonThomas/Axiom/issues/19) · [Release gate](https://github.com/DanielssonThomas/Axiom/issues/20) | [#16](https://github.com/DanielssonThomas/Praxis/issues/16), [#19](https://github.com/DanielssonThomas/Praxis/issues/19) and [#24](https://github.com/DanielssonThomas/Praxis/issues/24) need the applicable upstream qualification and real Praxis fixtures. |

Token counts in one API response describe the turn that produced them. Context-window occupancy, costs, and metering coverage for native workers still need to be measured. Surface, OS and version gaps remain open until evidence is merged.
